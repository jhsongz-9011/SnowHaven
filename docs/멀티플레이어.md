# 멀티플레이어 (1단계: 릴레이 서버)

## 구조
- `server/index.ts`: Node + `ws`. 각 클라이언트가 보낸 자기 상태를 모아 15Hz 로 모두에게 뿌린다 (서버 시뮬레이션 없음, 클라이언트 권위).
- `src/net/protocol.ts`: 메시지 규약과 검증(`parsePlayerView`). 서버·클라이언트가 같이 import.
- `src/net/net.ts`: 연결·재접속(2,4,8,16,30초 백오프)·내 상태 전송. 서버가 없어도 혼자 정상 플레이.
- `src/net/remote-players.ts`: 다른 플레이어 렌더 (보간 + 속도 외삽, 기울기/넘어짐 연출은 `rider-motion.ts` 공유).

## 실행
```
npm run server      # ws://localhost:8787 (PORT 환경변수로 변경)
npm run dev         # 클라이언트. 서버 주소는 VITE_WS_URL (기본 ws://현재호스트:8787)
npm run nettest     # 서버 통합 테스트
```

## 동기화하는 것
모든 모드 공통으로 월드 위치·방향·위쪽 벡터, 장비, 앉음 여부, 넘어짐 상태/경과 시간, 속도, 회전 속도.
(리프트 승강장/의자/활강 어디서든 같은 방식)

## 서버 방어
메시지 크기 2KB, 초당 40건 제한, 값 범위·타입 검증, 최대 40명, IP당 8연결, 첫 상태 5초 / 이후 15초 무응답 시 종료, 이상 이동 감지(아래).

## 이상 이동 감지 (`server/anomaly.ts`)
서버는 시뮬레이션을 하지 않으므로 "있을 수 없는 값"만 거른다. 상수는 `ANOMALY`.
- 주장한 속도가 장비 최고 속도 x 1.25 + 2 를 넘으면 깎고 위반 점수 +1
- 이동 거리는 누적 "이동 예산"(최고 속도 x 1.5 로 차오르고 상한 60 m)으로 검사. 메시지마다 여유를 새로 주지 않아 스피드핵이 통과하지 못한다
- 예산을 넘는 이동은 "점프". 리프트 건너뛰기/R 재시작/승강장 복귀 같은 정상 순간이동을 위해 5회까지 허용(20초에 1회 회복), 초과분은 이전 상태로 고정(다른 사람에게는 그 자리에 머물러 보임), 10초 넘게 고정되면 연결 종료
- 위반 점수는 초당 0.1 씩 줄고 20 을 넘으면 연결 종료(코드 1008)
- 클라이언트는 이동 연출(transfer) 중에는 출발 위치를 보내고 도착 후 새 위치를 보낸다 → 서버에는 순간이동 1회로 보인다 (`buildMyView`)
- 한계: 첫 메시지 위치는 자유, 허용 횟수 안의 임의 순간이동 가능, 재접속하면 점수/횟수 초기화(IP 단위 기억은 안 함), 장비 종류·상태·방향은 검사하지 않음. 발표용으로는 충분한 수준

## 아직 없는 것 (다음 후보)
충돌·기록 공유, 실제 호스팅 리허설(Render), 원격 플레이어 눈가루/자국.

## 코드 리뷰 반영 (보안/안정성)
- 서버: 모든 소켓에 error 리스너(닫는 중 큰 프레임으로 프로세스가 죽던 문제), IP당 8연결, 처음 상태를 5초 안에 안 보내면 종료, 송신 버퍼 256KB 초과 시 종료, 방향 벡터 길이 검증·정규화.
- 클라이언트: 서버 메시지를 `parsePlayerView` 로 다시 검증, 원격 한 명이 오류를 내면 그 플레이어만 제거, 방향 벡터가 0이 되는 경우 대체값 사용, IPv6 호스트 URL.
- 남은 것: 정지한 플레이어의 미세한 끊김(서버 타임스탬프 필요).

## 닉네임 / 인원 (결정 사항)
- 닉네임: 서버가 접속 때 **색 + 사물 + 동물**로 랜덤 생성 (예: "노란 열쇠 늑대"), 현재 접속자와 겹치면 다시 뽑음. 단어 목록은 `src/net/protocol.ts` 의 `THINGS/COLORS/ANIMALS`.
- 이름표는 머리 위 스프라이트, 70 m 밖에서는 숨김 (`REMOTE.labelDist`).
- 방 나누기: 하지 않음 (한 방). 채팅: 사용하지 않음.
- 최대 인원 40명 (`NET.maxPlayers`). 서버 송신량은 인원² 로 늘어난다: 16명 ≈ 5 Mbps, 32명 ≈ 22 Mbps, 40명 ≈ 34 Mbps, 64명 ≈ 87 Mbps. 더 늘리려면 가까운 사람만 보내기(관심 영역)나 이진 압축이 필요.

## 배포 — 발표(수업 시간 한정) 용도
서버가 화면(dist)까지 같이 내보낸다: 주소 하나만 열면 게임이 뜨고 멀티플레이도 같은 주소로 연결된다 (개발 중 vite 로 열 때만 8787 포트로 따로 접속).
- 로컬 실행(저장소 루트에서): `npm run build` → `npm run server` → 브라우저에서 `http://localhost:8787`. 화면 폴더는 `STATIC_DIR` 환경변수(기본 `dist`)로 바꿀 수 있다. `npm run preview` 는 서버가 아니므로 멀티플레이가 안 된다(쓰려면 `VITE_WS_URL` 지정).
- 컨테이너: `Dockerfile` (2단계: 클라이언트 빌드 → 서버+dist). 포트는 `PORT`, 상태 확인은 `/health`, 프록시 뒤에서는 `TRUST_PROXY=1`.
- 호스팅(Render 무료 웹 서비스 1개면 충분): GitHub 저장소 연결 → Docker → 환경변수 `TRUST_PROXY=1`, Health Check Path `/health`. 무료 서비스는 15분 동안 요청이 없으면 잠들고 다시 켜지는 데 약 1분 걸리므로 **발표 10분 전에 주소를 한 번 열어 깨워 둔다**.
- 백업(호스팅 장애/교실 방화벽 대비): 발표 PC 에서 서버를 켜고 터널(예: Cloudflare Quick Tunnel `cloudflared tunnel --url http://localhost:8787`)로 공개 주소를 만든다. 같은 와이파이라면 `http://<PC IP>:8787` 도 된다 (이 경우 https 가 아니므로 wss 불필요).
- 서버는 포트 사용 중/처리 안 된 예외 시 종료(재시작에 맡김), SIGTERM 에서 정상 종료, 컨테이너는 non-root(node)로 실행.
- 정적 파일은 시작할 때 dist 를 메모리에 한 번만 올려 두고 그 목록에 있는 경로만 준다(폴더 밖/심볼릭 링크/널바이트 불가). gzip·ETag(304)·nosniff 적용, html 은 no-cache (재배포 직후 옛 파일로 흰 화면이 되는 것 방지). 전체 약 1.5MB.
