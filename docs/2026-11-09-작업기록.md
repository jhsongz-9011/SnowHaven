# 2026-11-06 ~ 11-09 작업 기록 — 멀티플레이어와 발표용 배포 준비 (v0.1)

## 요약
혼자 타던 게임을 여러 명이 한 슬로프에서 같이 타는 게임으로 확장했다. 서버는 Node.js + WebSocket 릴레이,
접속자는 랜덤 닉네임(사물 + 색 + 동물)과 이름표를 갖는다. 사용 목적은 **수업 시간 발표 중에만 접속**하는 것이라
서버가 게임 화면(dist)까지 같이 내보내는 "주소 하나" 구조로 만들었다. 이 시점을 1차 마무리(v0.1)로 한다.

## 1. 멀티플레이어 (상세: `docs/멀티플레이어.md`)
- 구조: 클라이언트가 자기 상태를 15Hz 로 보내고, 서버는 검증 후 모두에게 스냅샷을 15Hz 로 뿌리는 릴레이 (서버 시뮬레이션 없음)
- 원격 플레이어: 지수 보간 + 속도 외삽(최대 0.15초) + 25m 넘으면 순간이동. 모델·기울기·웅크림·넘어짐 연출은 내 캐릭터와 같은 파라미터 (`src/net/remote-players.ts`, `src/rider-motion.ts`)
- 서버 방어: 페이로드 2048B, 연결당 초당 40개, 값 범위/타입/단위벡터 검증, 최대 40명, IP당 8연결, 5초 안에 첫 상태가 없으면, 이후 15초 무응답이면 종료, 송신 버퍼 256KB 초과 종료, 프록시 뒤 IP는 `TRUST_PROXY` 로만 신뢰
- 닉네임: 서버가 접속 때 생성(예: "열쇠 노란 늑대"), 겹치면 재추첨. 이름표는 머리 위 스프라이트, 70m 밖 숨김
- 결정 사항: 방 나누기 없음(한 방), 채팅 없음
- 인원 감각: 서버 송신량은 인원² (16명 5Mbps, 32명 22Mbps, 40명 34Mbps)

## 2. UI / 모바일
- 접속 상태 표시: 내 닉네임, 연결 점, 접속자 수 (서버 미연결이면 "혼자 플레이 중")
- 390px 폭에서 겹침 수정(장비 바, 안내 문구, 접속 표시), 터치 전용 기기에서는 터치 안내 문구
- 하이브리드 기기(터치 + 마우스/키보드)는 키보드 안내 유지

## 3. 발표용 배포 구조
- 서버가 `dist` 를 시작 시 메모리에 올려 목록의 경로만 제공 (경로 탈취/심볼릭 링크/널바이트 불가), gzip·ETag·nosniff, html 은 no-cache
- 빌드된 클라이언트는 같은 주소로 WebSocket 접속 (개발 중에만 8787)
- 멀티스테이지 Dockerfile(non-root), `/health`, SIGTERM 정상 종료, 포트 사용 중/처리 안 된 예외 시 종료
- 호스팅 계획: Render 무료 웹 서비스 1개(발표 10분 전에 주소를 열어 깨워 둘 것), 백업은 발표 PC 에서 서버 실행(같은 와이파이 또는 터널)

## 4. 검증
- `npm run build`(서버 타입 검사 포함), `npm run simtest`, `npm run nettest`(접속/중계/검증/한도/큰 프레임/닉네임/정적 서버) 통과
- 헤드리스 브라우저 두 개: 서로 보임, 같은 주소 접속, 나가면 사라짐, 모바일 해상도 스크린샷
- 코드 리뷰(서브에이전트) 4회: 서버 크래시(닫는 중인 소켓 오류), 영벡터로 렌더 깨짐, IP 한도 우회(X-Forwarded-For), 이름 유실, 정적 서버 캐시 메모리·시작 경쟁·재배포 흰 화면 등을 수정
